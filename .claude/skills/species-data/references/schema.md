# Схема на данните за видовете (енциклопедия и обитатели)

Написано според реалния код в `index.html` (проверено при версия 3.6.57).

## 1. Справочниците

Два масива във вградения скрипт:

| Масив | Ред (приблизително) | Брой записа | Съдържание |
|---|---|---|---|
| `animalsDB` | ~1385 | 87 | риби (72) и безгръбначни (15) |
| `plantsDB` | ~1476 | 43 | растения (type "Растение") |

Допълнителни производни списъци:
- `shrimpItems = animalsDB.filter(a => a.isShrimp)` (~1687)
- `aggressiveItems = animalsDB.filter(a => a.aggressive)` (~1688)
- `RENAMED_SPECIES` (~1476, над `plantsDB`) — алиаси за преименувани видове.

## 2. Полета на един запис

```js
{ name: "Неонова тетра (Neon Tetra)",
  type: "Риба",                       // "Риба" | "Безгръбначно" | "Растение"
  temp: "22-26°C",                    // текст, диапазон
  ph: "6.0 - 7.0",                    // текст, диапазон
  minLiters: 38,                      // число, минимален обем (л)
  food: "Люспи, микрогранули",        // текст; при растения: "Светлина: ..."
  compat: "Миролюбива, стадна (мин. 6 бр.)", // текст за съвместимост
  litersPerFish: 2,                   // число; 0 при растения и при някои безгръбначни
  aggressive: false,                  // boolean
  isShrimp: true }                    // по желание (само 8 записа)
```

Всички 130 записа имат задължително: `name`, `type`, `temp`, `ph`, `minLiters`, `food`, `compat`, `litersPerFish`, `aggressive`.
`isShrimp` е опционално и има само при 8 записа (скариди).

## 3. Формат на името

- Вид: `"Българско име (English name)"`. Пример: `"Сиамски водораслояд (Siamese Algae Eater)"`.
- Частта в скоби е английското име и се ползва за `I18N` превода.
- На български `speciesName()` (~4963) показва само частта преди ` (`; на английски `tr()` връща превода.
- **Името е ключът за всичко.** Обитателите в аквариума се свързват с видовете чрез точно съвпадение на `name`.

## 4. Превод (I18N)

- Всеки български текст на записа (`name`, `temp`, `food`, `compat` и др.), който се показва, трябва да има ключ в `I18N` (~4019).
- Ключът е точно същият низ като в `animalsDB`/`plantsDB`.
- Ако липсва превод, на английски се показва българският текст.

## 5. Как се съхраняват видовете при потребителя

Обитателите се пазят в `tank.fish` като копие на записа от справочника плюс:

```js
{ ...известния_запис,               // всички полета от горе
  count: 2,                          // брой
  note: "тест бележка",              // до 200 символа
  noteAt: 0, addedAt: 0, updatedAt: 0 }
```

При запис (`captureTank`, ~6115) се пазят само: `name`, `count`, `note`, `noteAt`, `addedAt`, `updatedAt`. Останалите полета се вземат от справочника при зареждане.

Това означава:
- Името в запазените данни трябва да съвпада със справочника, иначе записът се губи.
- Преименуване на вид в справочника без алиас **изчезва** при следващо зареждане (`cleanTank`, ~5105).

## 6. Алиаси за преименувани видове

```js
const RENAMED_SPECIES = {
    "Сиамски водорасложад (Siamese Algae Eater)": "Сиамски водораслояд (Siamese Algae Eater)"
};
```

Използва се на три места:
- `cleanTank` (~5111) — при зареждане, импорт и облачно изтегляне.
- Зареждане на любимите видове (~2111) — ключ `aquaAssistFavSpecies`.

Алиасът **не** се ползва в споделения/QR изглед (`renderLockedViewScreen`, ~3759), който показва името от линка.

Когато преименуваш вид:
1. Смени `name` в `animalsDB` или `plantsDB`.
2. Смени `I18N` ключа.
3. Добави стария → новия в `RENAMED_SPECIES`.
4. Провери с тест, че запазено състояние със старото име се зарежда и броят се запазва.

## 7. Проверки преди комит

- `node --check` върху извлечения скрипт (виж `CLAUDE.md`).
- Всеки `name` да е уникален (няма дубликати в `animalsDB` + `plantsDB`).
- Всеки `name` да има `I18N` ключ, ако е показван на английски.
